# 第一篇 · 预训练（Pre-training）：让模型"读万卷书"📖

## 一、预训练到底是什么？

老师用了一个特别形象的比喻：

> 「**预训练就像把一个小孩丢到一个图书馆里，让他自己去学习，阅读一些书籍**。它里面的那些数据从互联网上扒下来直接投喂，中间没有人干预，它自己去学习。」

### 用大白话翻译：
- **干啥**：把全网能找到的数据（书、网页、论文、代码…）一股脑塞给模型
- **目标**：让模型学会人话的规律——下一个词最可能是什么
- **特点**：**人不干预**，模型自己学，所以叫"无监督学习"
- **产出**：一个 **base model（基础模型）**，啥都懂一点但啥都不精

### 📋 它和我们日常用的 ChatGPT/Claude 区别在哪？

| 维度 | base model（裸模型） | 我们用的 GPT/Claude |
|------|------------------|------------------|
| 阶段 | 预训练完了就停 | 还经过了 SFT + RLHF |
| 行为 | 像个百科全书 | 像个会聊天的助手 |
| 例子 | 你问"你好"，它可能给你来一段维基百科介绍 | "你好！有什么可以帮你的吗？" |

> 🤔 **我的疑问**：那为什么需要后面的步骤？不是数据越多越好吗？  
> 💡 **想通了**：因为 base model 只学了"语言长什么样"，没学"怎么对话、怎么帮人"。就像一个读了很多书但不会和人交流的呆子。

---

## 二、3 个必须记住的名词 ⭐

老师反复强调这三个词面试和工作都会问：

### 2.1 涌现（Emergence）

> **定义**：在数据、算力、算法三要素持续堆叠下，模型突然出现一种新能力。

老师的金句让我印象深刻：

> 「就像武侠小说里的男主角功力到达某个节点突然打开任督二脉一样。」

🌰 **真实案例**：ChatGPT 从 3 到 4，参数量上去了之后，**突然出现了多模态和高阶推理能力**——这是研究员事先没预料到的。

```
     模型能力
       │
       │              ╱─── 涌现！突然会推理了
       │            ╱
       │          ╱
       │     ___╱
       │___╱
       └─────────────────► 数据/参数/算力
       临界点之前几乎没变化
```

> 🔍 **课后查了下**：业界有个著名实验叫"GSM8K 数学题测试"，小模型几乎全错，但当参数量到一定规模后准确率突然飙升。这就是涌现。

### 2.2 参数（Parameter）

> **大白话**：参数 = 模型的"脑容量"

| 参数规模 | 类比 | 代表模型 |
|---------|------|---------|
| 7B-10B | 高中生脑子 | Qwen 7B、Llama 7B |
| 几十B | 大学生 | Llama 70B |
| 100B+ | 教授 | GPT-4、Claude Opus |
| 千亿+ | 院士 | DeepSeek V4（1.6万亿） |

参数越多 → 能存的东西越多 → 学到的越丰富。

### 2.3 幻觉（Hallucination）

> **定义**：模型一本正经地胡说八道——生成不符合事实、凭空捏造的内容。

**幻觉为什么会产生？**（老师讲了 3 个原因）

| 原因 | 解释 | 例子 |
|------|------|------|
| 🗑️ **数据错误** | 训练数据本身就是错的 | 网上谣言被当真喂给了模型 |
| ❓ **数据缺失** | 模型没学过这个领域 | 问最新新闻它就编 |
| 🎲 **TOKEN 预测概率问题** | 选词时选错了，后面顺着错 | "李白是宋代诗人……" |

> 🤔 **思考**：第三个原因最有意思——模型生成是逐字预测概率，**一旦中间选错一个词，后面就会自圆其说继续编**，这就是为什么有时候模型回答看起来逻辑通顺但事实全错。

### 🚨 老师的"斯皮金定律"（这个名字好怪…可能是 Scaling Law 的口音版？）

> **核心**：模型能力 ≠ 无限堆料。**存在一个临界点，越过之后能力反而下降！**

🌰 **真实案例**：豆包 seed 2.0 会同时训练多个同代号模型，从中选出最好的发布——因为他们也不知道哪一版最强。

> 🔍 **我猜老师说的"斯皮金"应该是 Scaling Law（缩放定律）**——OpenAI 早期论文提出的：模型性能与数据/算力/参数呈幂律关系。但确实有研究表明超过一定规模后边际收益递减。

## 三、预训练的 4 个步骤

```
1. 数据收集 ────► 2. 预处理 ────► 3. 分词 ────► 4. 神经网络训练推理
   (扒数据)        (清洗分类)       (变成模型     (模型学习+生成)
                                    能看懂的)
   
   🟡 训练师参与    🟡 训练师参与    🔴 算法主导    🔴 算法主导
```

**AI 训练师在哪一步？**

> 主要在**前两步**，而且**只在做模型的公司**才参与。比如要重新构建一个医疗领域模型，前期需要把扒下来的数据分类——动物类、人像类、植物类分别存放。一般公司用现成的 base model，这两步训练师都不沾。

> 🌰 **老师的话**：「预训练阶段 AI 训练师参与较少，多数工作来自后训练。」

# 第二篇 · 后训练（Post-training）：让模型"会做人"🎓

> ⭐ **重点来了！这一段是 AI 训练师的主战场。**

## 五、为什么要后训练？

预训练完的 base model 像个"读了很多书但不会和人打交道的呆子"。

后训练的目标是：

```
通用型人才 ────► 专项人才
   │                │
   ▼                ▼
什么都懂          特定任务做得好
   │                │  
   ▼                ▼
不知道用户要啥     懂人类喜欢什么
   │                │
   ▼                ▼
   ────► 与人类对齐（Alignment）
```

## 六、后训练的两个阶段

```
            🍼 base model
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
   阶段一: SFT          阶段二: RLHF
   (有监督微调)         (人类反馈强化学习)
        │                   │
   告诉模型               让模型学会
   "这种回答是对的"        "什么样的回答更受人喜欢"
        │                   │
        ▼                   ▼
   做项目: 单轮问答         做项目: Reward Model
            多轮问答                    排序
            COT 思维链
```

> 💡 **我的理解**：SFT 是教**怎么做对**，RLHF 是教**怎么做更好**。

## 七、SFT（Supervised Fine-Tuning）有监督微调

### 7.1 SFT 在干啥？

老师举了个特别接地气的例子：

> 「在 SFT 阶段，**如果想让模型把笑话讲好，就可以通过人为干预去构建一批笑话的数据投喂给模型**，让模型知道我们人类喜欢怎么样的笑话，知道什么样的笑话我们人类会笑。」

简单说就是：**精挑细选一批"标准答案"喂给模型，让它学会某类对话的套路**。

### 7.2 SFT 三大项目（训练师主要做这些）

| 项目 | 数据形式 | 难度 | 老师举例 |
|------|---------|------|---------|
| 1️⃣ **单轮问答** | 一问一答 | ⭐⭐ | 汽车售前售后问答 |
| 2️⃣ **多轮问答** | 多回合连续对话 | ⭐⭐⭐⭐ | 客服多轮咨询 |
| 3️⃣ **COT 思维链** | 问题 + 推理过程 + 答案 | ⭐⭐⭐⭐⭐ | 数学题分步推导 |

## 八、单轮问答项目实战 🎯

### 8.1 训练师的工作流程（4 步）

```
1. 撰写规则文档
   ↓
2. 构建高质量数据
   ↓ 数据来源：算法提供 OR 自己构建（爬取/模型生成）
   ↓ 注：构建后的数据要人工审核！
3. 把控标注过程质量
   ↓
4. 数据复盘
```

### 8.2 数据怎么"提升质量"？两条路

老师讲了个核心方法叫"**对存量单轮数据的 response 进行质量提升**"：

> ⚠️ 注意：**重点是改 response（回答），不是改 query（问题）**。

| 方法 | 操作 | 何时用 |
|------|------|-------|
| 🧠 **人为主观判断** | 自己读，凭经验改 | 简单常识题 |
| 🔄 **参考竞品** | 看 GPT/Claude 怎么回答，借鉴优点 | 复杂或专业题 |

### 8.3 标注时要填什么？

| 字段 | 作用 |
|------|------|
| 错误类型 | 比如"事实错误"/"指令不遵循"/"格式问题" |
| 问题备注 | 具体哪里错了 |
| 标注原因 | 为什么这么判 |

> 💡 **重要**：**便于溯源！** 后来回看为什么这条改成这样，得能找到依据。

### 8.4 处理策略

```
看到一条数据 ──► 这个 response 是什么级别？
                    │
        ┌───────────┼────────────┬────────────┐
        ▼           ▼            ▼            ▼
       完美         有小问题     问题严重     难度过大
        │           │            │            │
        ▼           ▼            ▼            ▼
       通过 ✅      改写 ✏️      舍弃 ❌      跳过 ⏭️
                                              (改写难度过大)
```

> 🔍 **改写难度判断**（老师讲的细节）：
> - 文本错误 < 50%：自己改一两句
> - 文本错误 > 50%：跳过（不改了，保留原数据但标记为"差"）
> - 仅需改个词或一句话：直接改

## 九、判断数据"优质 vs 不优质"的 4 大维度 ⭐⭐⭐

> 这是这周最重要的知识点之一！面试肯定会问。我画了个金字塔：

```
       优先级（从上到下）
       ┌─────────────────┐
       │  🔴 1. 安全     │  ← 一票否决，最重要
       ├─────────────────┤
       │  🟠 2. 指令遵循 │
       ├─────────────────┤
       │  🟡 3. 内容质量 │
       ├─────────────────┤
       │  🟢 4. 语言表达 │  ← 加分项
       └─────────────────┘
```

### 9.1 🔴 安全维度（首位！）

数据出现以下情况**必须舍弃**：
- 涉政、涉法
- 黄、赌、毒
- 违反价值观（地域歧视、抹黑他人等）

> ⚠️ 这个一定要严，老师说面试问规则维度排序，**安全永远排第一**。

### 9.2 🟠 指令遵循维度

| 情况 | 解释 | 例子 |
|------|------|------|
| **完全不遵循** | 答非所问 | 问"今天天气"答"我喜欢吃苹果" |
| **部分遵循** | 只答了一部分 | 让"用'你好'开头，'再见'结尾，中间说人生" → 只说了人生 |
| **不合理拒答** | 合理问题被拒 | 问"详细解释分子机制"被拒答 |
| **问题有误** | 提问本身有问题 | 问"圆的边长是多少" |

### 9.3 🟡 内容维度（5 个小项）

| 维度 | 含义 | 易错点 |
|------|------|-------|
| **准确性** | 知识不能错、推理不能错 | ⚠️ 推理错但结果对 → 是否通过？看规则文档 |
| **价值丰富度** | 多角度提供信息 | 单一角度算扣分 |
| **贴切性** | 符合用户需求/情绪 | 用户难过时，要安抚而不是讲段子 |
| **时效性** | 给最新信息 | 别给 2020 年数据当 2026 年说 |
| **权威性** | 来源权威 | 医疗题 → 三甲医院文章；不是知乎 |

### 9.4 🟢 语言维度

| 维度 | 含义 |
|------|------|
| **内容表达** | 通顺、标点正确 |
| **格式表达** | 按要求排版（如 Markdown、序号） |
| **话术冗余** | 别废话，简单问题别复杂化 |
| **思路混乱** | 不能多条逻辑互相打架 |

## 十、过拟合 & 欠拟合（扩展知识，老师顺带讲的）

> 这俩词机器学习老朋友了，但很多人记不清。

| 概念 | 通俗解释 | 像什么 | 怎么解决 |
|------|---------|-------|---------|
| **过拟合**（Overfitting） | 学得太死，只认训练数据 | 死记硬背的学生，考试换个题型就懵 | 增加数据量 + 多样性 |
| **欠拟合**（Underfitting） | 学得不够，连训练题都做不对 | 没好好上课的学生 | 提升数据质量 + 调整模型架构 |

```
    模型表现
       │           ╱╲ 完美
       │         ╱    ╲ 过拟合
       │      ╱  
       │    ╱  欠拟合
       │  ╱
       └────────────────► 训练时长/数据量
       
       学得太少：欠拟合（笨）
       学得刚好：泛化能力强 ⭐
       学得太多：过拟合（死板）
```

> 🤔 **联想到我自己**：备考的时候做太多同类型题，结果换了题型考砸——这就是我自己的"过拟合"😂

## 十一、规则文档怎么写？（标准模板）

> 这个是老师**反复强调**的训练师核心交付物，也是我们之前一直没系统学的部分。

### 11.1 必备模块

```
规则文档（v1.0）

┌──────────────────────────────────────┐
│ 1. 项目背景（S4T AR 法则） ⭐         │
│    - 现状/问题（Situation）           │
│    - 任务（Task）                    │
│    - 行动（Action）                  │
│    - 结果（Result）                  │
├──────────────────────────────────────┤
│ 2. 概要方案                          │
│    - 数据来源、量级                   │
│    - 交付周期、准确率                 │
├──────────────────────────────────────┤
│ 3. 标注规则（4 大维度）⭐⭐⭐         │
│    - 安全 / 指令 / 内容 / 语言       │
│    - 每个维度 + case 示例            │
├──────────────────────────────────────┤
│ 4. 标注方案                          │
│    - 线上/线下                       │
│    - 用哪个标注平台                   │
├──────────────────────────────────────┤
│ 5. 排期                              │
├──────────────────────────────────────┤
│ 6. badcase / goodcase 示例           │
└──────────────────────────────────────┘
```

> 🤔 **S4T AR 是啥？** 老师讲得快，我记了下来后来一查——应该就是 **STAR 法则**（Situation-Task-Action-Result），HR 圈很常用，简历也用这个。可能老师手抖打成 S4T 了。

### 11.2 撰写关键原则

> 💎 **金句**：「所有的数据好坏是否优质不是我们评判，个人主观去判断的，**都是要有规则文档去约束判断的**，如果这个规则文档乱了，就大家都乱了。」

| 原则 | 解释 |
|------|------|
| 🎯 **以小白视角** | 想象一个新来的标注员能不能看懂 |
| 📊 **可视化** | 表格、流程图，别全是文字 |
| 🌰 **一定要有 case** | 正例 + 反例都给出 |
| 💼 **换位思考** | 销售员只关心数据怎么做、规则维度，别讲一堆理论 |
| ✂️ **简洁实用** | 老师吐槽自己昨天写的"小爱问答"文档**太长，反而降低标注效率** |

### 11.3 用大模型写规则文档（提效技巧）

老师建议借助 PE（提示词工程）来生成规则文档：

**两段式提示词法**：

```
第一段：让模型了解项目大概
"我要做一个 [项目名]，背景是 [...]，
数据类型是 [...]，给我一个规则文档框架。"

→ 模型给出框架后，问它：
"那你需要我提供什么样的数据示例才能输出更好的规则？"

→ 模型回复后

第二段：把示例放进去
"基于上面的框架，参考这些示例 [data]，
请输出完整规则文档，要求 [格式/约束]。"
```

> 💡 **关键**：不要一次性把所有需求都给它，**分两段对话效果更好**。

> 💎 **金句**：「prompt 的好坏真的决定着你这个结果是否优质。」

## 十二、多轮对话项目（多轮 vs 单轮）

### 12.1 核心区别

```
单轮：                        多轮：
Q1 → A1                       Q1 → A1
                              Q2 → A2  (要参考 Q1A1)
（一锤子买卖）                Q3 → A3  (要参考 Q1A1Q2A2)
                              ...
                              （一直要保持上下文一致）
```

### 12.2 多轮特有的 3 个规则维度

| 维度 | 含义 | 易错例子 |
|------|------|---------|
| **指代省略** | 第二轮可以用"他/她/这个"指代前文 | 不能每轮都重复全名 |
| **重复摘抄** | 后续回答如果 30%-40% 抄第一轮 → 算问题 | 模型偷懒抄上文 |
| **上下文一致** | 必须遵守第一轮设定的规则/约束 | 第一轮说"你是律师"，第二轮变成厨师 |

🌰 **老师举例**：
- 第一轮："给我介绍一下刘亦菲"
- 第二轮："**她**演过哪些电影？" → 模型要懂"她"=刘亦菲

### 12.3 标注方案

| 方式 | 操作 | 何时用 |
|------|------|-------|
| 全标 | 每一轮都标 + 改写 | 数据量小、要求高 |
| 单轮标 | 只标某一轮，其他轮作上下文 | 大批量、提效 |

### 12.4 一个反直觉的细节 ⚠️

> 老师强调：**开启新项目要开启新对话**！

🌰 为什么？比如你前一轮在和 Claude 聊数学题，开启新对话还问数学题——**模型可能会被前一轮的逻辑串到后面**，污染答案。

> 🤔 **我以前还真没注意过**，下次写 prompt 都要"清场"。

## 十三、强化学习（RLHF）：让模型学会人类的偏好 🏆

### 13.1 RLHF 是啥？

> **RLHF = Reinforcement Learning from Human Feedback**  
> **基于人类反馈的强化学习**

老师说理想中的强化学习"暂时无法处理"，所以现在用 RLHF 替代。

### 13.2 核心思路：训练一个"奖励模型"

```
原理像下面这样：

一个问题（query）
    │
    ├──► GPT 答案 A
    ├──► Claude 答案 B
    ├──► Kimi 答案 C
    └──► 自家模型 答案 D
    
     ↓ 人工排序
     
   D > A > C > B（举例）
   
     ↓ 投喂给奖励模型
     
   奖励模型学会"什么样的答案人类更喜欢"
   
     ↓ 拿这个奖励模型
     
   去训练大模型 → 输出更符合人类偏好的内容
```

### 13.3 训练师的工作

| 步骤 | 训练师做什么 |
|------|------------|
| 1. 收集 query + 多个模型答案 | 算法提供 / 自己构建 |
| 2. **排序** ⭐ | 人工对答案从好到差排序 |
| 3. 必要时补充满分回答 | 当所有答案都不行时 |

### 13.4 排序方法：两两对比 ⭐

> 这个超有意思，像选美打擂台：

```
4 个答案 A B C D：

   A vs B → A 胜
   A vs C → A 胜  
   A vs D → A 胜    A 最强 → 第 1
   
   B vs C → B 胜    
   B vs D → D 胜    
   
   C vs D → D 胜    D 第 2
                    B 第 3
                    C 第 4
                    
   最终排序：A > D > B > C
```

> 🤔 **类比**：就像找对象，让你直接说出喜好排序很难，**但两两对比就容易得多**——"A 和 B 你更喜欢谁？"

### 13.5 三人一致性原则

为了降低主观性：
- 一般 **3 人** 标注同一条数据
- 取多数（2:1）的排序
- **3 人都不一样** → 继续标注，直到达成一致
- 真的搞不定 → 开会讨论 / 项目群求助专家

### 13.6 规则维度排序（提效技巧）

> 老师讲了个超棒的提效方法：**前 3 个维度固定（安全 > 指令遵循 > 内容质量），后续按项目目标排序。**

🌰 比如旅游项目就把"贴切性""丰富度"往前排；金融项目就把"权威性""时效性"往前排。

> ⚠️ **盲标方式**：质检采用盲标（不让标注员看到别人怎么标），人数以基数为宜（3、5、7…），出现不一致再加人。

# 第三篇 · COT 思维链：让模型"学会想问题"🧠

> 这是 5月3日上午的内容，我觉得是这周**最有意思**的一节！

## 十四、为什么需要 COT？

### 14.1 老师的开场太搞笑了

老师举了一些早期模型搞不定的事：

| 任务 | 早期模型 | 现在 |
|------|---------|------|
| "Strawberry 有几个 r？" | 答 2 个（错） | 推理后答 3 个 ✅ |
| "9.11 和 9.9 哪个大？" | 答 9.11（错，按字典序） | 推理后答 9.9 ✅ |
| "生成恰好 100 字" | 经常溢出 | 推理后能控字数 ✅ |
| "中文偏旁部首识别" | 完全不行 | 还是不太行（中文优势不明显） |

### 14.2 快思考 vs 慢思考（认知科学概念）

> 这部分老师没展开讲，我**课后查了下**，挺有意思：

诺贝尔奖得主丹尼尔·卡尼曼在《思考，快与慢》里把人脑分两套系统：

| 系统 | 特点 | 例子 |
|------|------|------|
| **System 1（快思考）** | 直觉、自动、快速 | "1+1=?" 不假思索答 2 |
| **System 2（慢思考）** | 逻辑、推理、费力 | "23 × 47 =?" 需要分步算 |

> 💡 **没有 COT 之前的模型只有快思考**——一上来就答，错了也不知道。  
> **有了 COT，模型能慢思考**——先拆步骤、推理、验证，再给答案。

## 十五、COT 是什么？

### 15.1 定义

> **COT (Chain of Thought) = 思维链**  
> 一种用于提升大语言模型推理能力的技术，通过在问答和答案之间插入中间推理步骤，模拟人类解决问题的思考过程。

### 15.2 怎么实现？（重要：无需改模型本身！）

```
没 COT：
Q: 23 个苹果分给 5 人，每人几个余几个？
A: 每人 4 个余 3 个。  ← 直接回答，对错全凭直觉

有 COT：
Q: 23 个苹果分给 5 人，每人几个余几个？
A: 让我想想：
   - 23 ÷ 5 = ?
   - 5 × 4 = 20
   - 23 - 20 = 3
   - 所以每人 4 个，余 3 个
```

> ⭐ **重点**：**COT 不改模型参数，只改提示词！** 这是它的魅力——成本低、灵活。

### 15.3 三种实现方式（按强度递增）

```
1. COT 提示词工程   2. SFT 有监督微调   3. RLHF 强化学习
   ↓                    ↓                  ↓
   一句话搞定          构建带推理的数据    用奖励模型训练
   成本低 + 效果差     成本高 + 效果强    最强 + 最复杂
   "灵活派"            "正规派"            "终极派"
```

### 15.4 COT 提示词的 3 种形式

| 类型 | 做法 | 例子 |
|------|------|------|
| **Zero-shot（0样本）** | 加一句"让我们一步步思考" | "Let's think step by step" |
| **Few-shot（少样本）** | 给几个推理示例 | "示例：Q1...A1（含推理）；现在 Q2 类似回答" |
| **Auto（自动）** | 让模型自己生成推理路径 | 类似强化学习 |

## 十六、COT 的优缺点

### ✅ 优点

| 优点 | 解释 |
|------|------|
| 1️⃣ **提高准确率** | 复杂问题分步骤就不容易错 |
| 2️⃣ **增加用户信任感** | 看到推理过程，用户觉得"嗯，这模型靠谱" |
| 3️⃣ **便于纠错改进** | 错了能找到哪一步出错，标注员可针对性改写 |

### ❌ 缺点

| 缺点 | 解释 |
|------|------|

| 3️⃣ **不是万能的** | 简单任务（如"今天几号"）开 COT 反而拖慢速度 |

## 十九、COT 项目训练师怎么干？

### 19.1 任务目标

> **确保模型的"思考部分"和"答案"都优质。**

数据结构是这样的：
```json
{
  "prompt": "用户问题",
  "think": "模型的推理过程",  ← 这部分要标注
  "response": "模型的答案"     ← 这部分也要标注
}
```

### 19.2 标注规则（5 大维度）

| 维度 | 含义 |
|------|------|
| 1️⃣ **需求理解充分准确** | 模型懂用户在问啥 |
| 2️⃣ **推理完善** | 步骤齐全，没跳步 |
| 3️⃣ **推理逻辑合理** | 每一步都对 |
| 4️⃣ **信息获取量高** | 用了相关知识 |
| 5️⃣ **有效反思** | 模型自我纠错 |

### 19.3 有效反思 vs 无效反思（这个细节很重要）

| 类型 | 例子 | 判定 |
|------|------|------|
| ✅ **有效反思** | "等等，我前面 23×4 算成了 96，应该是 92，重新算……" | 推理质量+ |
| ❌ **无效反思** | "嗯…让我再想想…可能是…也可能不是…" | 冗余废话 |

### 19.4 标注步骤（实操）

```
1. 看到一条数据 (prompt + think + response)
   │
   ▼
2. 判断该不该舍弃？
   ├─ 文创类（散文/诗歌）→ 舍
   ├─ 太专业（量子物理）→ 舍
   ├─ 无法验证真伪 → 舍
   └─ 安全类 → 舍
   │
   ▼
3. 没舍弃的，对比择优
   ├─ 拿竞品（GPT/Claude）的 think 对比 → 选好的
   └─ 拿竞品的 response 对比 → 选好的
   │
   ▼
4. 改写
   ├─ 自家 think 烂 → 用竞品的或自己写
   └─ 自家 response 烂 → 用竞品的或自己写
```

### 19.5 实战例子：长方体鱼缸问题（老师课上案例）

> Prompt：长方体鱼缸长 10、宽 5、高 8，求体积。

| 模型 think A | 模型 think B |
|------------|-------------|
| "嗯让我想想，体积要乘起来…大概…我再确认下…等等，先算 10×5=50，然后×8…哦还是不对…再来…" | "体积 = 长 × 宽 × 高 = 10 × 5 × 8 = 400" |
| ❌ 大量重复、表达冗余、无效反思 | ✅ 简洁、准确 |

→ 选 think B，对 think A **改写**

# 第四篇 · Agent：让模型"学会做事"🤖

> 5月3日下午第一节。终于讲到酷炫的 Agent 了！

## 二十一、什么是 Agent？

### 21.1 定义（背一下）

> **Agent = 由大语言模型驱动的、具备决策和行动能力的自主系统，能处理复杂任务，整合规划、记忆、工具调用等能力，是从"回答问题"到"解决问题"的下一代智能系统。**

### 21.2 老师的比喻

> 「**Agent 可以比喻为贴身小秘书**——比如点奶茶时，能根据你过往记忆帮你选。」

```
普通 LLM：               Agent：
你：今天点啥奶茶？        你：今天点啥奶茶？
LLM：奶茶有很多选择……    Agent：根据你过去 3 次都点
                              "霸王茶姬伯牙绝弦不另冰
                              不另糖"，我帮你下单了？
                              当前店里 8 折活动！
```

> 💡 **核心区别**：LLM 是"百科全书"，Agent 是"会做事的助理"。

## 二十二、Agent 的三大能力（核心！）

```
                Agent 大脑
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
     1.规划       2.记忆       3.工具调用
     Planning    Memory       Tools
        │           │           │
        ▼           ▼           ▼
   分解任务       长期/短期    调用 API
   思维链         记忆系统     完成动作
   自我反思
```

### 22.1 规划（Planning）

| 子能力 | 解释 | 例子（用 Cursor） |
|-------|------|----------------|
| **任务分解** | 把大任务拆成步骤 | "做一个植物识别脚本"→ 1.获取API 2.写脚本 3.测试 |
| **思维链推理** | 每一步用 COT 推 | 边做边想 |
| **自我反思** | 评估产出，纠错 | 发现 bug 自动修 |

> 💡 **CoT 在 Agent 里的位置**：思维链是 Agent 规划的核心机制。前面学的 COT 在这里又用上了！

### 22.2 记忆（Memory）

```
记忆分两种：

📚 长期记忆 (Long-term)         💭 短期记忆 (Short-term)
   │                              │
   像知识库                        像聊天上下文
   │                              │
   ▼                              ▼
- 你的过往订单                   - 当前对话历史
- 偏好（不另冰、不另糖）          - 当前任务参数
- 永久保存                       - 关闭对话就忘
```

> 💡 **训练师不参与这部分**——老师明确说"记忆部分由算法同学负责，因为涉及数据库等算法需求"。

### 22.3 工具调用（Tool Use）⭐ 训练师重点参与！

```
用户："帮我订明天下午 3 点北京到上海的高铁"
              │
              ▼
        Agent 思考：
              │
        我需要调用：
        ├─ 时间工具（获取明天日期）
        ├─ 12306 API（查票）
        ├─ 支付工具（付钱）
              │
              ▼
        逐个调用 → 完成
```

| 训练师在工具调用做啥？ |
|--------------------|
| 🎯 **选择**：判断这个场景该用哪个工具 |
| ✏️ **标注**：给模型标记"对这个 query，应该调用工具 A" |
| 🔧 **改写**：模型选错工具时，改正 |

## 二十三、ReAct 框架（扩展知识，老师没细讲我课后查的）

> 老师提到一个词 "React 框架"，我以为是前端那个 React，差点跑偏…查了下原来是 AI 圈的另一个 ReAct！

> **ReAct = Reasoning + Acting**

它是 Agent 的底层执行框架，核心是**循环**：

```
   ┌────────►   Thought   （思考：我要干啥？）
   │              │
   │              ▼
   │           Action     （行动：调用什么工具）
   │              │
   │              ▼
   └─────── Observation  （观察：工具返回了啥）
              │
              ▼
        最终答案 / 继续循环
```

🌰 **真实例子**（来自论文）：

```
Q: 除了 Apple Remote，还有什么设备能控制它最初设计的程序？

Thought: 我需要先知道 Apple Remote 最初设计是为什么程序。
Action: 搜索 "Apple Remote 最初设计程序"
Observation: 是 Front Row。

Thought: 然后我需要知道 Front Row 还能被什么控制。
Action: 搜索 "Front Row 控制设备"
Observation: 键盘的 F 键和 Apple Remote。

Thought: 答案出来了。
Final Answer: 键盘的 F 键。
```

> 💡 **总结**：Agent 不是一上来就执行，而是 **思考→行动→观察→再思考** 的循环。这就是为什么 Agent 比普通 LLM 强 —— 它不会一条道走到黑。

## 二十四、Agent 案例：会议室助手

### 24.1 数据结构

```json
{
  "user_prompt": "帮我订今天下午1点的会议室",
  "agent": {
    "think": "用户要订今天下午1点。我需要先看现在几点了…",
    "action": "调用获取当前时间工具"
  }
}
```

### 24.2 运行规则（重点）

| 规则 | 含义 | 例子 |
|------|------|------|
| **过期提醒** | 用户预定时间 < 当前时间 → 提醒 | "今天下午1点已过，无法预定" |
| **工具复用** | 之前调用过的工具不重复调 | 已知今天日期，下次别再问"今天几号" |

### 24.3 标注规则

```
看到一条 (prompt + think + action)：

│
├── think 对 + action 对 → 标 1（通过）
│
├── think 错 / action 错 → 标 0（不通过）
│   │
│   ├─ 改写 think
│   └─ 改写 action
│
└── 太复杂改不动 → 舍弃
```

### 24.4 标注 8 步流程（老师讲的，记下来）

```
1. 阅读项目背景
2. 理解工具定义（每个工具能干啥）
3. 检查 user prompt 是否合理
4. 检查 agent 的 think 是否合理
5. 检查 agent 的 action 是否合理
6. 改写不对的部分
7. 自检（再读一遍是否通顺）
8. JSON 格式验证
```

> ⚠️ **特别注意**：JSON 格式验证！标错括号、漏逗号都会让数据废掉。

# 第五篇 · RAG：让模型"会查资料"📚

## 二十五、什么是 RAG？

### 25.1 定义

> **RAG = Retrieval-Augmented Generation**  
> **检索增强生成**

老师的解释：

> 「核心作用是**给大模型外挂专门的知识库**，让查出来的资料更准、更新、更贴合用户的需求。」

### 25.2 用大白话说

```
没 RAG 的模型：              有 RAG 的模型：
                              
你问：我们公司Q3销量？        你问：我们公司Q3销量？
模型：我不知道你们公司…        系统：先去公司知识库查
                              ↓
                              找到《Q3财报.pdf》
                              ↓
                              模型基于财报回答
                              "Q3销量 1.2亿，同比+15%"
```

## 二十六、为什么要做 RAG？4 大理由

| 理由 | 解决什么问题 |
|------|------------|
| 1️⃣ **解决幻觉** | 数据缺失 → 用知识库补 |
| 2️⃣ **专业领域** | 通用模型不懂车企售后政策 → 内部 RAG 解决 |
| 3️⃣ **时效性** | 模型有训练截止时间 → 联网 RAG 给最新 |
| 4️⃣ **可解释性** | 答案带角标、可溯源 → 用户敢信 |

> 💡 **RAG 解决的是"幻觉"中的"数据缺失"那一块**——但解决不了"数据错误"和"概率预测错"那两块。

### 离线 vs 在线 RAG

| 类型 | 特点 | 适用场景 |
|------|------|---------|
| **离线 RAG** | 本地知识库，私有化数据 | 企业内部（车企、医院） |
| **在线 RAG** | 联网搜索 | 需要最新信息（新闻、股票） |

## 二十七、RAG 的工作原理（核心！）

> 这部分老师讲得有点快，我**课后查了向量数据库的原理**才完全搞懂。

### 27.1 完整流程图

```
【准备阶段】（一次性，存知识库）

公司文档（PDF/Word/Excel/PPT）
        │
        ▼
   按段落/语义/章节切分（chunk）
        │
        ▼
   embedding 模型转成向量（一串数字）
        │
        ▼
   存入向量数据库


【运行阶段】（用户每次提问）

用户提问 query
   │
   ▼
embedding 转成向量
   │
   ▼
向量数据库找最相似的 N 个 chunk
   │
   ▼
原始 query + 召回的 chunk → 增强 prompt
   │
   ▼
喂给大模型 → 生成答案（带引用）
```

### 27.2 三个关键概念（搞清楚这三个就懂 RAG 了）

#### 🔢 Embedding（向量化）

> **把文字变成一串数字。**

🌰 比如：
- "苹果" → `[0.12, 0.85, -0.34, ...]`
- "Apple" → `[0.13, 0.87, -0.32, ...]` （和"苹果"接近）
- "汽车" → `[-0.9, 0.21, 0.5, ...]`  （差很远）

> 💡 **核心**：意思相近的词，向量也相近。**向量距离 = 语义相似度**！

#### 🗄️ 向量数据库

> **专门存向量、并能快速找"最相似向量"的数据库。**

普通数据库找数据靠精确匹配（你查"苹果手机"它就找"苹果手机"）；  
向量数据库找数据靠语义匹配（你查"水果旗舰机"它也能找到"苹果手机"）。

#### 🎯 检索（Retrieval）

> 用 **余弦相似度** 找最相近的几个 chunk。比较的是向量"方向"，不是长度。

```
              "苹果手机"
                  ↑
          ╱ ╱     │
        ╱ ╱       │ "iPhone"
      ╱ ╱ "水果旗舰机"
    ╱ ╱
   ── ── ── ── ── 越靠近角度越相似
```

## 二十八、Top K 是啥？

老师提了一句"按 top k 值召回"——这个我**查了一下**：

> **Top K = 检索时返回最相似的前 K 个 chunk。**

| K 值 | 优点 | 缺点 |
|------|------|------|
| K=3 | 信息少，模型不分心 | 可能漏相关内容 |
| K=10 | 信息全 | **模型注意力被稀释，反而答得差** |

> ⚠️ 老师上周讲过的："**模型输入内容越多生成结果越烂**"——这就是为什么不能 K 设太大！

## 二十九、训练师在 RAG 里干啥？

```
准备阶段                    生成阶段
   │                          │
切分策略制定                判断生成内容质量 ⭐
构建高质量数据集              ↓
   │                       这是训练师重点
   ▼                          
👤 协助算法                👤 主要工作
```

### 29.1 RAG 数据 3 要素

```
一条数据 = 问题 + 参考材料 + 回答
                Question  Reference  Answer
```

### 29.2 判断标准

| 维度 | 通过标准 | 跳过 / 改写情况 |
|------|---------|---------------|
| **问题** | 逻辑清晰、语义明确 | 难懂 / 历史对话错误 / 涉黄涉暴 → 跳过 |
| **参考材料** | 相关、准确、全面 | 与问题不相关 / 事实错误 / 内部冲突 → 跳过 |
| **回答** | 无语病、逻辑通、意图正确 | 严重问题 → 改写或舍弃 |

### 29.3 改写策略（实操）

```
看到一条数据：

3 个参考回答都不合格？
   │
   ├─ 都不合格 → 择优改写（选字数少、改起来简单的）
   │
   ├─ 部分合格 → 三合一融合 / 提取正确部分组成新答案
   │
   └─ 真不行 → 跳过（但**不能滥用跳过**！）
```

> ⚠️ **重要规则**：**数据错误率达到 50%-70% 以上才能跳过**。因为数据量有限，跳多了交付不够。

### 29.4 跳过的"合理理由"（老师总结的 3 类）

```
1. 作答成本过高（要花太多时间）
2. 自我能力不足（改不动）
3. 超出能力范围（专业到看不懂，如量子物理）

→ 这三类都可以"心安理得"地跳过
```
